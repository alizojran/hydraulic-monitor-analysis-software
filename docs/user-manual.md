## 1. 快速开始

### 1.1 启动方式

**Web 模式（推荐）**

```bash
cd v2
npm install
npm run dev
```

打开浏览器访问 `http://localhost:5173/`。

**生产部署**

```bash
npm run build
# 把 v2/dist/ 部署到任意静态服务器（nginx / Apache / IIS / GitHub Pages）
```

**桌面模式（可选）**

如果需要离线运行，可以编译 Tauri 桌面壳（需要 Rust 工具链）：

```bash
cargo tauri build
```

### 1.2 浏览器要求

| 项目 | 最低 | 推荐 |
| --- | --- | --- |
| WebGL2 | 必须 | Chrome 120+ / Edge 120+ |
| ES2022 | 必须 | Safari 17+ / Firefox 121+ |
| WebSerial（硬件采集） | 仅 Chromium 内核 | Chrome / Edge |

> 移动端浏览器可以打开，但 13 路 GL 画布同时渲染会比较吃力，仅建议查看不建议长时间运行。

### 1.3 第一次启动

进入软件后会自动启动**模拟器**——一组物理耦合的合成波形（泵的脉动、谐波、轴承故障特征、声学噪声）会立即出现在所有面板上。这意味着你不需要任何硬件就能熟悉所有功能。

如果要切换到真实数据，请见下文 [数据源接入](#3-数据源接入)。

## 3. 数据源接入

软件支持 5 种数据源。在**实时**或**历史**视图顶部的"数据源切换器"可以选择。

### 3.1 模拟器

默认数据源。一组与转速耦合的合成波形：

- **压力脉动**：与 RPM × 活塞数（默认 7 缸）成比例
- **振动谐波**：1×、2×、3× RPM 谐波
- **轴承故障特征**：BPFI / BPFO / BSF 频率注入
- **声学噪声**：粉红噪声 + 周期性脉冲

**用途**：演示、培训、回归测试。

### 3.2 CSV 文件

**操作**：拖拽 CSV/TSV 文件到实时视图任意位置，或者点击"打开 CSV"按钮。

**自动检测**：

- 时间戳列（识别"timestamp" / "time" / "ts" / "datetime" 等）
- 分隔符（`,` / `;` / `\t` / `|`）
- 通道列名（与 `channels.ts` 中 13 个通道 ID 匹配）

**进度**：超过 10 万行的文件会显示进度条，分块解析在 Web Worker 中完成，主线程不卡顿。

### 3.3 WAV 文件

适用于声学数据回放。`AudioContext.decodeAudioData` 解码后映射到 `acoustic` 通道，可以播放、暂停、拖动进度。

### 3.4 WebSerial（硬件直连）

**前提条件**：

- Chrome / Edge 浏览器（不支持 Firefox / Safari）
- DAQ 设备通过 USB 串口连接（STM32 / Arduino 等）
- 设备固件按 `docs/communication-protocols.md` 输出帧格式

**操作**：

1. 数据源切换器选择"WebSerial"
2. 点击"连接设备" → 浏览器弹出端口选择器
3. 选择对应 COM 口 → 连接成功后 LED 指示变绿

### 3.5 WebSocket（远程后端）

**前提条件**：后端服务（包括 Modbus 代理）暴露 WebSocket 端点输出 JSON 帧。

**操作**：

1. 数据源切换器选择"WebSocket"
2. 输入 ws:// 或 wss:// 地址
3. 点击"连接"

**典型用法**：CODESYS PLC → WebSocket gateway → 浏览器，或多客户端共享同一 DAQ 服务（监控端 + 操作端 + PAD）。

## 5. 频谱分析

### 5.1 主要面板

```
┌──────────────────────────────────────────────────────────┐
│   FFT 主图（线性 / dB / 1/3 倍频带切换）                   │
│   ↑ 鼠标悬停显示游标 + 频率/幅值                           │
│   ↑ 轴承故障频率虚线（BPFI/BPFO/BSF/FTF）                  │
│   ↑ GMF 齿轮啮合频率紫色线（启用后）                        │
├──────────────────────────────────────────────────────────┤
│   SpectrumControls — 窗函数 / FFT 大小 / 平均次数 / 阶次切换│
├──────────────────────┬───────────────────────────────────┤
│   FaultSummaryPanel  │   WaterfallChart 瀑布图           │
│   (规则引擎诊断)      │                                   │
├──────────────────────┤                                   │
│   AIDiagnosisCard    │                                   │
│   (展开后显示 AI 结果)│                                   │
├──────────────────────┤                                   │
│   OctaveBandChart    │                                   │
│   1/3 倍频带柱状      │                                   │
└──────────────────────┴───────────────────────────────────┘

         BearingDiagnosticPanel (轴承几何 + 故障表)
```

### 5.2 FFT 控制面板（SpectrumControls）

| 项目 | 选项 | 默认 | 说明 |
| --- | --- | --- | --- |
| **窗函数** | Hamming / Hanning / Blackman / FlatTop / Rect | Hanning | FlatTop 用于精确读幅值，Hanning 通用 |
| **FFT 大小** | 512 / 1024 / 2048 / 4096 / 8192 | 2048 | 大值频率分辨率高，小值时间分辨率高 |
| **重叠率** | 0 / 25% / 50% / 75% | 50% | 高重叠率画面更平滑 |
| **平均次数** | 1 / 4 / 8 / 16 / 32 | 4 | 数值越大噪声越低，瞬态丢失 |
| **频率轴** | Hz / 阶次 (Order) | Hz | 阶次模式跟随 RPM 自动归一化 |

### 5.3 轴承诊断（BearingDiagnosticPanel）

#### 添加轴承

1. 点击 **+ 添加轴承**
2. 在弹出表单选择预设型号（SKF 6205 / 6206 / 6308 / 6310 / NSK / FAG 等）或手动输入几何参数
3. 几何参数：滚珠数 (Z)、节圆直径 (Pd)、滚珠直径 (Bd)、接触角 (α)
4. 系统自动计算 BPFI / BPFO / BSF / FTF 四个特征频率，根据当前 RPM 实时刷新

#### 故障频率覆盖

频谱主图顶部会出现**虚线**：

- 红色 — BPFO（外圈）
- 橙色 — BPFI（内圈）
- 绿色 — BSF（滚珠）
- 青色 — FTF（保持架）

#### 故障判定（FaultSummaryPanel）

规则引擎在每次 FFT 输出后运行：

1. 在每个故障频率 ±tolerance 窗口内取峰值
2. 计算与噪声底的 SNR
3. 按 SNR 阈值映射严重度：`none / watch / warning / critical`

## 6. 历史数据

### 6.1 会话浏览

软件每次"开始"会创建一个 **session**，记录起始时间、数据源、采样率、持续时长。

历史视图显示所有会话列表，点击任意一行可以回放其录制的波形。

### 6.2 加载外部文件

通过数据源切换器加载 CSV 或 WAV 文件后，会自动进入回放模式。

**回放控制**（PlaybackControls）：

- 播放 / 暂停
- 拖动时间轴跳转到任意位置
- 调整播放速度（0.25× / 0.5× / 1× / 2× / 4×）

### 6.3 数据持久化

会话元数据保存在 `localStorage` 中（`hmas-sessions` key），波形原始数据**不**保存（避免占满浏览器配额）。需要长期保存请用导出功能（见第 10 节）。

### 7.1 视图布局

```
┌─────────────────┬──────────────────────────────────┐
│  AlarmRuleEditor│   AlarmTimeline   │ AlarmStats   │
│  规则列表 + 编辑 │   24h 时间轴       │ 严重度饼图   │
```

### 7.2 添加报警规则

1. 左侧 **+ 添加规则**
2. 表单字段：
   - **通道**：从 13 路通道中选一个
   - **类型**：阈值上限 / 阈值下限 / 速率
   - **阈值**：触发数值
   - **持续时间**：连续 N 秒满足条件才触发（防止瞬时尖峰误报）
   - **严重度**：low / warn / high
   - **标签**：人类可读的描述
3. **保存**

### 7.3 事件日志

事件按时间倒序，每行包含：

- 严重度徽章
- 时间戳
- 通道
- 描述
- 触发数值
- 状态：active / acknowledged / resolved
- **AI 诊断列**（仅当启用了 AI 时）：
  - "待反馈" 按钮 — AI 已诊断完成，等你录入实际维修结果
  - 故障类型文本 — 已完整闭环
- **确认** 按钮（active 状态）

### 7.4 统计图

- **AlarmTimeline**：过去 24 小时按小时分桶的事件直方图
- **AlarmStatsChart**：所有事件按严重度的饼图

### 7.5 报警 + AI 联动

在配置 → 设备档案 → AI 配置中开启 **"高严重度告警自动触发"** 后：

1. 高严重度规则上升沿触发
2. 系统创建 AlarmEvent
3. 自动调用 `runDiagnosis('alarm', alarmEventId)`
4. AI 分析结果挂在该 AlarmEvent 上，事件日志显示"待反馈"
5. 维修后点击"待反馈"录入实际结果，进入闭环学习

详细见第 9 节。

## 9. 设备档案与 AI 诊断

### 9.1 整体思路

通用 LLM 不知道**这台具体的泵**有多旧、平时振动多大、上次换轴承是什么时候。AI 诊断的核心方法是：

1. 用户为设备建立**3 层档案**
2. 每次诊断时把档案 + 当前测量 + 历史摘要拼成提示词
3. 调用 Claude API → 返回结构化 JSON 诊断结果
4. 维修后录入实际结果 → 进入设备历史 → 下次诊断更准

3 层档案：

| 层 | 内容 | 来源 |
| --- | --- | --- |
| **1. 静态元数据** | 型号、品牌、安装日期、额定参数、轴承规格 | 手动填一次 |
| **2. 工况基线库** | 9 个工况下的振动指纹（健康状态） | 一键采集 60 秒 |
| **3. 历史诊断日志** | 历次 AI 诊断 + 实际维修结果 | 软件自动记录 |

### 9.2 第一次配置（约 5 分钟）

#### 步骤 1：填基本信息

进入 **配置 → 设备档案 → 基本信息** 标签：

| 字段 | 示例 |
| --- | --- |
| 设备编号 | 主泵 A01 |
| 品牌 | Rexroth |
| 型号 | A10VO45DFR/31R |
| 安装日期 | 2022-03-15 |
| 额定转速 | 1480 rpm |
| 额定流量 | 50 L/min |
| 最高压力 | 280 bar |
| 工作油温 | 40 – 65 °C |
| 安装方式 | 卧式 / 立式 |
| 安装环境 | 室内 / 户外 / 防爆 / ... |
| 备注 | 任何额外信息 |

#### 步骤 2：添加轴承

下方"轴承配置"区域，点击 **+ 添加轴承**：

- 位置：DE（驱动端）/ NDE（非驱动端）/ 自定义
- 型号：从预设下拉选择（SKF 6205 / 6206 / 6308 / NSK 6204 / FAG 22320 等），自动填入几何参数
- 上次更换日期：可选，便于跟踪轴承寿命

#### 步骤 3：导出/导入档案

为了便于在多台同型号设备间复用：

- **导出档案** → 下载 JSON 文件（不含 API Key）
- **导入档案** → 选择 JSON 恢复

### 9.3 建立工况基线库

工况按 9 个桶分类：

| 转速 | < 600 rpm | 600 – 1200 rpm | > 1200 rpm |
| --- | --- | --- | --- |
| **轻载** (压力 < 40%) | LOW_LIGHT | MID_LIGHT | HIGH_LIGHT |
| **额定** (40 – 80%) | LOW_NOMINAL | MID_NOMINAL | HIGH_NOMINAL |
| **重载** (> 80%) | LOW_HEAVY | MID_HEAVY | HIGH_HEAVY |

#### 操作步骤

1. **确认设备健康** — 这是关键前提。基线只在设备健康时建立。
2. 让设备进入某个稳定工况（例如以 1480 rpm + 200 bar 运行 5 分钟）
3. 进入 **设备档案 → 工况基线库** 标签
4. 顶部"当前工况"会显示自动判定的桶（例如 `HIGH_NOMINAL`）
5. 该行点击 **建立基线**
6. 系统在 60 秒内每 2 秒采样一次，最终保存平均值
7. 完成后该行显示 RMS / CF / BPFI / BPFO 数值

#### 后续维护

- 换轴承后 → 重建该工况基线
- 基线超过 2 年 → 行尾出现 ⚠️ 提示，建议重建
- 删除某工况 → 点击 ×

### 9.4 配置 AI

进入 **设备档案 → AI 配置**：

| 字段 | 说明 |
| --- | --- |
| **AI 服务商** | 当前仅 Anthropic Claude |
| **API Key** | `sk-ant-...` 格式，[官网申请](https://console.anthropic.com/) |
| **模型** | claude-opus-4-7（最强）/ claude-sonnet-4-6（推荐）/ claude-haiku-4-5（最便宜） |
| **月度预算** | USD 上限，达到后非手动触发会跳过 |
| **本月已用** | 实时累计 |
| **启用 AI 分析** | 总开关 |
| **高严重度告警自动触发** | 报警上升沿自动跑诊断 |
| **测试连接** | 发个最小请求，验证 Key 可用 |

> **API Key 安全**：Key 通过 AES-GCM（PBKDF2 派生）加密存储在浏览器本地，导出档案时**不会**包含 Key。仅在可信设备上输入。

### 9.5 运行 AI 诊断

#### 手动触发

1. 进入 **频谱视图**
2. 找到右侧 **AI 分析** 卡片，点击展开
3. 点击 **🤖 重新分析**
4. 看到流式响应（边接收边显示）
5. 完成后显示：
   - 故障类型 + 严重度徽章
   - 置信度（高/中/低）
   - **关键证据**（列表）
   - **建议措施**
   - 元信息（生成时间、模型、本次成本 USD）
   - 如果模型建议停机，会显示橙色警告条

#### 自动触发

按 9.4 配置启用后，高严重度告警上升沿会自动调用，结果出现在告警视图的"AI 诊断"列。

#### 提示词预览

如果 AI 未启用或 Key 没填，点击"重新分析"时不会发请求，但会在卡片底部显示**完整提示词预览**（折叠的 details 块），让你看到将会发送的内容。

### 9.6 反馈闭环

维修后必须录入实际结果，否则 AI 不会进步。

#### 操作

1. 报警视图 → AI 诊断列出现 **待反馈** 黄色按钮
2. 点击 → 弹出反馈表单：
   - 检查日期
   - 实际发现（自由文本）
   - **AI 诊断正确性**：是 / 否 / 未检查
   - 采取措施：换轴承 / 继续观察 / 换密封 / 其他（多选）
   - 更换部件型号
   - 维修后 RMS（可选）
   - **重建基线** 复选框（推荐勾选）
   - 备注
3. 点击 **保存结果**
4. 如勾选重建基线，会自动开始 60 秒采集

#### 数据流向

每次诊断 + 反馈成为一条 `DiagnosticEvent`，附加到设备历史日志。

- 原始事件最多保留 20 条
- 超过 20 条时，最老的 15 条会被 LLM 压缩成不超过 300 字的中文摘要
- 下次诊断时把"压缩摘要 + 最近 5 条"作为"设备历史"段注入提示词

### 9.7 月度预算监控

AI 配置面板的"本月已用"实时累加。月份切换会自动归零（按月初本地时间）。

非手动触发（即自动告警触发）在预算用尽后会跳过，避免一次故障刷爆账单。手动点击"重新分析"始终可以执行，由用户兜底。

## 10. 数据导出与报告

### 10.1 截图导出

任意 GL 画布右键 → "另存为图片"，或者顶部栏的 **截图** 按钮（导出当前视图为 PNG，使用 html-to-image）。

### 10.2 数据导出（CSV / JSON）

使用 `useExport` 组合式函数，目前接入位置：

- **频谱视图** → 导出当前 FFT（频率 + 幅值表）为 CSV
- **报警视图** → 导出事件列表为 CSV
- **历史视图** → 导出当前会话原始波形（CSV）

### 10.3 报告生成

`useReport` 组合式函数生成包含截图 + 数据表 + AI 诊断结果的 HTML 报告。

接入位置：频谱视图 → 工具栏 → **生成报告** 按钮（如果存在）。

报告内容：

- 设备档案头
- 当前 FFT 截图
- 故障频率表
- 规则引擎结论
- AI 诊断结果（如有）
- 时间戳 / 操作员（待扩展）

## 11. 常见问题

### Q1: AI 诊断卡片显示"AI 未启用 — 显示提示词预览"

→ 进入配置 → 设备档案 → AI 配置：
- 检查 API Key 是否填写
- 检查"启用 AI 分析"是否打开
- 点"测试连接"验证 Key 可用

### Q2: API 调用 401 错误

→ Key 错误或过期。重新填写 Key，确保前缀是 `sk-ant-`。

### Q3: API 调用 429 错误

→ 触发了 Anthropic 速率限制。等几秒重试，或者切换到更便宜的 haiku 模型。

### Q4: API 调用 CORS 错误

→ 软件已经设置了 `anthropic-dangerous-direct-browser-access: true` header。如果仍报错可能是浏览器扩展拦截或公司代理问题，尝试无痕模式。

### Q5: 基线采集中转速突然下降到 0

→ 系统会照常完成 60 秒采样并取平均；但建议删除该基线后在转速稳定时重建。

### Q6: 报警事件丢失

→ 检查配置 → 系统 → 存储占用。事件最多保留 2000 条。如果存储配额报警 (`hmas-storage-quota` 事件)，最老的事件会被自动丢弃。考虑定期导出 CSV 归档。

### Q7: localStorage 配额满

→ 系统会自动派发警告。手动清理：配置 → 系统 → **清空所有本地存储**（注意会丢失所有配置），或浏览器开发者工具 → Application → Local Storage → 删除最大的 `hmas-*` 或 `daq-*` key。

### Q8: WebSerial 找不到设备

→ 仅 Chromium 内核浏览器支持。检查：
- 设备已通过 USB 连接
- 设备没有被其他软件占用（如串口终端、CODESYS）
- 浏览器在 HTTPS 或 localhost 环境（http://其他地址不允许）

### Q9: 实时画面卡顿、FPS 低

→ 13 路 GL 画布对老旧 GPU 是负担。优化方向：
- 配置 → 系统 → 降低 FPS 上限
- 关闭不需要的通道
- 关闭 spectrum 视图的瀑布图
- 切换到性能更好的浏览器（Chrome 通常 > Firefox > Safari）

### Q10: 中英文混杂

→ 顶部栏点击中文/English 切换；如果某处仍有未翻译的硬编码文本，在 GitHub Issues 提交报告，我们补 i18n key。
